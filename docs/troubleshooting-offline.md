# Troubleshoot offline use

The current supported offline method is a local production build served at `127.0.0.1`. Installer-, PWA-, and desktop-wrapper-specific messages normally indicate an unofficial package or an unsupported setup.

| Problem | Likely cause | Diagnostic step | Corrective action |
|---|---|---|---|
| Works online but not offline | The hosted Pages site or an incomplete browser cache was used | Check whether the address is `github.io` instead of `127.0.0.1` | Build the production application while online and launch the retained local build as documented. |
| WASM fails to load | Missing/corrupt `.wasm`, wrong URL, or server returned HTML | In Network tools, filter `wasm`; check status, content type, and local URL | Run `npm run build`, confirm a `.wasm` under `web/dist/assets`, and use `/genbank_viewer/` at the documented local address. |
| Blank screen | JavaScript/WASM failed, an asset path is wrong, or the browser is unsupported | Inspect Console and Network for the first error | Rebuild from a clean checkout with supported tools; use the exact local URL and a current browser. |
| `file://` URL fails | ES modules, absolute asset paths, and WASM require HTTP | Address begins with `file:///` | Start Vite preview and use `http://127.0.0.1:4173/genbank_viewer/`. |
| “Service-worker cache incomplete” | An unofficial PWA setup was attempted | Check Application/Storage tools for a service worker | Remove the unsupported PWA registration and use the local-build method; this project has no service worker. |
| Stale PWA version or browser removed cached data | Browser caching was mistaken for PWA installation | Confirm there is no genbank_viewer service worker/manifest | Rebuild or reload while online, or use retained local assets. Browser cache is not the supported offline store. |
| Local server is not running | Terminal was closed or process stopped | Open the local URL and check the terminal | Run `npm run preview -- --host 127.0.0.1` from `web` and keep it running. |
| Port 4173 is in use | Another process has the default port | Read Vite's terminal output; it may choose another port | Open the exact URL Vite prints, or stop the conflicting process. Keep the host bound to `127.0.0.1`. |
| Antivirus or SmartScreen warning | A tool or unofficial executable was downloaded | Identify the exact publisher, path, and checksum | The project supplies no installer. Stop and verify provenance; use institution-approved Git, Rust, Node.js, and source. |
| Linux “permission denied” for an AppImage | An unofficial or future AppImage was obtained | Check the project's current release assets | No AppImage is currently produced; use the documented local build rather than changing permissions. |
| Missing Linux webview dependency | An unofficial desktop wrapper was used | Identify the package that requested the webview | The supported build uses an ordinary browser and needs no Tauri/webview runtime. Obtain support from the package provider. |
| macOS Gatekeeper warning | An unofficial `.app` or executable was used | Check provenance and signing details | The project supplies no macOS app. Do not bypass Gatekeeper without an authorised security review; use the source-build method. |
| Chromebook cannot see a file | ChromeOS has not shared the location or Drive file is online-only | Copy a non-sensitive test file into Downloads or Linux files | Grant only the needed picker/share permission; mark Drive files available offline before disconnection or copy them locally. |
| Gzip file fails to open | Truncated/corrupt gzip, unsupported suffix, or insufficient memory | Try the repository's small `.gbk.gz` fixture and inspect the displayed error | Obtain a complete file named with a supported GenBank extension followed by `.gz`; close other tabs for large files. |
| Large genome freezes or exceeds memory | Compressed bytes, decoded text, records, render state, and browser overhead coexist in memory | Test a smaller representative record and monitor browser memory | Split exceptionally large multi-record files or use a computer/browser with more available memory. No fixed maximum is established. |
| Installer architecture mismatch | An unofficial installer or wrong tool architecture was used | Compare Windows x64/ARM64, macOS Intel/Apple Silicon, or Linux architecture | The project has no installer. Install build tools matching the computer and rebuild locally. |
| Package is unsigned | A third-party or future package lacks signing | Compare it with current official release information | No official package is currently published or signed. Do not infer trust from the filename; verify source and checksums under local policy. |
| Application attempts a network connection | Modified build, browser extension/service, future code, or unexpected dependency | Record destination, initiator, request data, and stack in Network tools | Stop using sensitive data; reproduce with the audited local build and clean browser profile. Report a reproducible application-originated request with evidence. |
| `npm`, `cargo`, or `wasm-pack` fails offline | Required packages/crates/toolchains were not cached | Re-run only on a connected preparation computer and identify the missing download | Prepare all dependencies online or transfer an already built, same-platform checkout including `web/node_modules`; do not expect an uncached source build to work offline. |

For parser, annotation, translation, and search issues that are not specific to offline launch, see the [general troubleshooting guide](troubleshooting.md).
